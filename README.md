# News Channel — science globe

A Wii News Channel–style 3D globe, populated from real bioRxiv preprints via
a scheduled GitHub Action. No backend, no API keys, no server to run.

## How it fits together

- `index.html` — the site itself. Fetches `stories.json` at load time; if
  that file doesn't exist yet (e.g. before the first snapshot run) it falls
  back to a small embedded sample so the page still works.
- `fetch_biorxiv_snapshot.py` — pulls recent bioRxiv preprints, resolves
  author institutions, scores/selects a manageable subset, and writes
  `stories.json`.
- `institutions.json` — the curated institution → coordinates lookup table
  the script matches affiliations against. Grow this by hand over time.
- `unmatched_affiliations.txt` — generated by the script; affiliation
  strings it couldn't match to anything in `institutions.json`. Your
  curation queue.
- `.github/workflows/snapshot.yml` — runs the script daily and commits the
  refreshed `stories.json` back to the repo.

## First-time setup

1. Create a new **public** GitHub repository.
2. Add these files at the repo root (keep the folder structure — the
   workflow file must stay under `.github/workflows/`):
   - `index.html`
   - `fetch_biorxiv_snapshot.py`
   - `institutions.json`
   - `.github/workflows/snapshot.yml`
3. Commit and push to `main`.
4. **Enable GitHub Pages:** repo → Settings → Pages → under "Build and
   deployment," set Source to "Deploy from a branch," Branch to `main` and
   folder to `/ (root)`, then Save. After a minute or two the site is live
   at `https://<your-username>.github.io/<repo-name>/`.
5. **Trigger the workflow manually to test it** (don't wait for the daily
   cron): repo → Actions tab → "Refresh news snapshot" → "Run workflow"
   button → Run workflow. This is the part that actually needs real
   internet access to `api.biorxiv.org`, which is why it has to run on
   GitHub's runners rather than being testable locally in this chat.
6. Once that run finishes (a minute or two — most of the time is the
   per-paper JATS XML fetch for institution resolution), check the repo:
   `stories.json` should now exist with real data, and
   `unmatched_affiliations.txt` may have appeared too.
7. Reload the Pages site. It should now be showing real preprints instead
   of the embedded sample.

From here it refreshes on its own once a day via the cron schedule — no
further action needed unless you want to change how much it pulls
(`--days`, `--pool-size`, `--max-stories` in the workflow file) or curate
`institutions.json` further.

## Things worth checking on that first real run

- How many candidates got dropped for zero resolved institutions — tells
  you how much `institutions.json` needs to grow.
- What shows up in `unmatched_affiliations.txt` — add the ones worth
  keeping to `institutions.json` with real coordinates.
- Whether ~30 stories over 3 days feels like the right density on the
  globe, or too sparse/cluttered — both are one-line changes in the
  workflow file (`--max-stories`, `--days`).
